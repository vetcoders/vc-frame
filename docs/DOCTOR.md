# The Config Clinic — `doctor` and `repair`

Two commands, one disease. A vc-frame config that was autogenerated once —
with `keybinds clear-defaults=true` and a full dump of the keybinds of the
day — **freezes the key contract forever**. The binary ships new verbs; the
config keeps answering with the old ones. Nothing errors, nothing warns, and
the guide describes a frame you are not running.

The clinic has two roles and they never blur:

- **`vc-frame doctor` — the diagnostician.** Read-only. Reads the config,
  applies the same layout overlay startup uses (`default_layout` /
  layout_dir), compares that **session-effective** contract against the one
  shipped in the assets, and reports. It never writes a byte. Config-only
  green is forbidden: a layout can inject keybinds after the config parse.
- **`vc-frame repair key-bindings` — the therapist.** Writes exactly one
  file, the user config, and only after a timestamped backup.

Not to be confused with `make doctor`, which checks the *build* environment
(cargo, wasm target, protoc). This clinic looks at the *runtime* config of an
installed vc-frame.

## Symptoms — when to run it

Run `vc-frame doctor` the moment any of these is said out loud:

| Symptom | What it usually is |
|---|---|
| "the chrome keys from the guide do nothing" | config shadowing — the guide reads the assets, your session reads the frozen dump |
| "Ctrl+q killed my whole session" | a frozen `Ctrl q → Quit` bind shadowing the shipped `Ctrl q → CloseFocus` |
| "vc-frame freezes every 30 seconds" | lock stranding — autolock is on, but LOCK mode has no navigation left except `Ctrl+g` |
| "session `x` / the rail hop do not exist here" | verbs added after the dump was frozen |
| "I fixed it in the source but nothing changed" | install freshness — the installed binary predates the checkout |

The shadowing class is not hypothetical. It cost two operator machines a
morning on 2026-07-30: a 262-line frozen block hid `Ctrl+q → CloseFocus`,
session `x` (kill the current session and hop to the next), and the rail
navigation inside LOCK — while the status bar honestly rendered `<q> QUIT`,
because that genuinely was the binding in force.

## A full run

Shape of the flow, not a byte-exact transcript:

```console
$ vc-frame doctor
── vc-frame doctor ──
[CONFIG SHADOWING]  CRITICAL  keybinds clear-defaults=true (170 binds)
    Ctrl q → Quit          (contract: CloseFocus)  ← kills the whole session
    session "x"            missing                (kill current session + hop)
    Alt ←→ / Alt ↑↓        missing                (product tab / session nav)
    locked Ctrl ←→ ↑↓      missing                (optional LOCK bonus)
[LOCK STRANDING]    WARN      auto_lock_after_seconds 30, LOCK knows only Ctrl+g
[INSTALL FRESHNESS] ok        binary matches checkout
[SHELL]             ok        /bin/zsh (caller environment — not the server process)
    → vc-frame repair key-bindings
exit 2

$ vc-frame repair key-bindings --dry-run   # plan only, writes nothing
$ vc-frame repair key-bindings
backup:  config.kdl → config.kdl.bak-20260730-0821
removed: keybinds block (clear-defaults=true), guard comment left in place
kept for you to re-apply as targeted overrides, if you still want them:
    Ctrl q → Quit ·  Alt f → ScrollToBottom ·  …
restart the session for this to take effect, then re-run: vc-frame doctor

$ vc-frame doctor
exit 0
```

The restart is not ceremony: a running session holds the config it started
with. Until you restart, `doctor` will keep reporting the old contract and be
right about it.

## Findings

| Finding | Severity | Meaning | Remedy |
|---|---|---|---|
| `config-shadowing` | CRITICAL | a shipped contract bind is shadowed by a dangerous one — canonically `Ctrl q → Quit` instead of `CloseFocus` | `vc-frame repair key-bindings` |
| `config-shadowing` | WARN | contract verbs simply absent: session `x`, session `r` (rail), LOCK navigation | same, or add the binds by hand |
| `lock-stranding` | WARN | `auto_lock_after_seconds > 0` while LOCK has no navigation beyond `Ctrl+g` — the frame appears to freeze every N seconds | repair, or set `auto_lock_after_seconds 0` |
| `install-freshness` | WARN | the installed binary is older than the checkout — a fix in the source that is not in the binary looks exactly like a fix that does not work | `make install` |
| `shell` | INFO | no `SHELL` in the **caller** environment (the process running `doctor`); the live server has its own env → passwd → `/bin/sh` chain | none; informational |
| `config-shadowing` | WARN | selected layout could not be analysed — doctor refuses to claim a match because layout may override keybinds | fix `default_layout` / `layout_dir`, or drop them for the built-in default |
| `config-parse` | ERROR | the config does not parse — vc-frame is running on defaults and your file is doing nothing | fix the reported KDL error |

Exit codes are the contract:

| Exit | Meaning |
|---|---|
| `0` | healthy, or INFO only |
| `1` | at least one WARN |
| `2` | at least one CRITICAL, or a config parse error |

`clear-defaults` can sit on the whole `keybinds` node **or** on a single mode
block. Both shadow; the per-mode form just shadows less, and is the harder one
to spot by eye. `doctor` reports either.

## What `repair key-bindings` actually does

1. **Backup, always** — `config.kdl` → `config.kdl.bak-<YYYYMMDD-HHMMSS>`,
   before any decision. No flag disables this.
2. **Block with `clear-defaults=true`** — removed *whole*. A partial cure is
   worse than none here: whatever stays keeps shadowing. In its place goes a
   guard comment saying why the block is intentionally absent and pointing at
   the backup. The binds that genuinely differed from the current defaults are
   printed for you, so a deliberate override can be re-added by hand — without
   `clear-defaults`, and without a dump.
3. **Block without `clear-defaults`** — only the binds that are semantically
   *identical* to the defaults are dropped. That is noise, not intent. Real
   overrides are left untouched.
4. **`--dry-run`** — prints the same plan and writes nothing. Use it first if
   the config is precious.
5. **Afterwards** — restart the session, then `vc-frame doctor` to confirm.

Everything else in your config — themes, options, layouts, plugin config — is
out of scope and untouched. The therapist treats keybinds only.

## Keeping a classic layout, on purpose

`clear-defaults=true` is a legitimate power-user choice. Our contract is
opinionated and someone will want the classic Zellij modes back. There are two
ways, and they are not equal.

**Sanctioned: the `configuration` plugin** — `Ctrl+o` then `c`. The shipped
presets ("Default", "Unlock-First") give you the classic mode layout *with*
the fork's safety corrections already folded in, `Ctrl+q → CloseFocus` first
among them. This is the recommended way back.

**Raw: your own `clear-defaults=true` dump.** It works, and it carries every
risk below.

| # | Risk | Weight |
|---|---|---|
| 1 | `Ctrl+q → Quit` returns — one keystroke tears down the whole session | CRITICAL |
| 2 | stranded in LOCK: autolock is an *option*, independent of keybinds; upstream LOCK knows only `Ctrl+g`, so no rail hop and no tab navigation | HIGH |
| 3 | session verbs vanish: `x` (kill current + hop), `r` (rail) do not exist upstream | MEDIUM |
| 4 | the guide describes the asset contract while a different one is in force | MEDIUM |
| 5 | upstream binds no `Super/Cmd` keys; asset product contract is the Cmd switcher (tabs/sessions, every mode) | LOW |
| 6 | Ctrl+arrows optional LOCK bonus — Mission Control may keep Spaces defaults | LOW |

If you take the raw path, pair it with `auto_lock_after_seconds 0` — or know
that `Ctrl+g` is your only way out of LOCK. Risk #2 must never be left silent.

`doctor` still reports a preset-generated block: not as an accusation, but so
the origin and the way back are named. A deliberate opt-in reads its own
report and moves on with exit 1 in hand.

## `--json` for agents and CI

`vc-frame doctor --json` emits the same findings as a machine document:

```json
{
  "version": 1,
  "exit_code": 2,
  "findings": [
    {
      "id": "config-shadowing",
      "severity": "critical",
      "title": "keybinds clear-defaults=true shadows the shipped contract",
      "detail": "Ctrl q → Quit (contract: CloseFocus); session \"x\" missing",
      "remedy": "vc-frame repair key-bindings"
    }
  ]
}
```

Contract for consumers: branch on `exit_code` and on `findings[].id` +
`severity` (`info` < `warn` < `critical`, plus `error` for parse failures).
Never parse the prose — `title` and `detail` are for humans and will be
reworded. In a CI or bootstrap flow, exit `2` is a hard stop; exit `1` is a
report worth surfacing to whoever owns the machine. Pair it with
`vc-frame setup --check` when you need the resolved config directory and the
full environment dump.
